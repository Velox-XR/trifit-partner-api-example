# Partner API application guidance

Read this only when the user asks how to apply for commercial Partner API access
or asks to prepare an application.

Call `get_partner_application_guide` for the current official workflow and
`get_partner_access_requirements` for provisioning requirements. The public
guidance does not submit a form, send email, inspect a mailbox, issue keys, or
activate access.

Prepare a draft using only details the user chooses to include. Project/use
case, company/platform, expected usage, and launch timing are optional. Do not
require a company or successful live test to explain the application process.

This developer documentation package has no mail connection. If the host already
provides a separately authorized email capability and the user asks to use it,
follow the current guide: confirm the connected sender, show the recipient,
subject and complete body, and obtain approval before sending. If that capability
is unavailable, leave the draft in chat. Do not add mailbox credentials, OAuth
permissions, or an email connector to this package.

A draft is not sent. A successful send means sent and awaiting acknowledgement,
not approved. An uncertain send must be reconciled against the original message
before any retry; do not submit a second application through another channel.
Report receipt or approval only when the corresponding response is actually
available. Commercial approval, credentials, and terms remain separate Velox
operations. A documentation request does not authorize a purchase or live
generation.
